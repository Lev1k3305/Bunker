# 🎲 SHELTER — сетевая игра на выживание

## Обзор проекта
- **Название**: SHELTER (рабочее название сменено с «Бункер» на англоязычное «SHELTER», чтобы не совпадать с брендом известной коммерческой настольной игры)
- **Цель**: полноценная сетевая игра-ролевая дискуссия о выживших в убежище после катастрофы. Реальные игроки заходят каждый со своего устройства по короткому коду комнаты, выбирают своё место, получают приватное досье (характеристики видны только им, пока они сами их не раскроют), проходят раунды раскрытия, обсуждают ситуации в общем чате и голосуют за исключение с ограничением по времени.
- **Особенности**:
  - **Комнаты с кодом**: любой может создать комнату (4–16 мест) и получить 5-символьный код; остальные подключаются по этому коду каждый со своего устройства
  - **Выбор своего места**: в лобби каждый сам занимает свободное место и вписывает своё имя — так определяется, кем он будет в игре
  - **Настоящая приватность на сервере**: в начале игры характеристики видит только их владелец; остальным игрокам они не передаются сервером вовсе, пока владелец сам их не раскроет (не «локальный peek», а честная серверная фильтрация на каждый запрос)
  - **Хост комнаты** — первый занявший место игрок; управляет катастрофой, бункером, раундами, ситуациями и голосованием
  - 80+ узкоспециализированных профессий, 16 детально прописанных катастроф, случайные параметры бункера
  - Полные карточки персонажей: пол/возраст, здоровье, фобия, хобби, черты характера (+/−), инвентарь, доп. информация
  - Раскрытие характеристик по клику — доступно только на своей карточке; переброс скрытых характеристик
  - **25 развёрнутых «Ситуаций»** для озвучивания вслух в любой момент партии — кнопка «Ситуация» у хоста
  - **Голосование с таймером**, разблокируется только начиная с 3-го раунда: у всех живых игроков ограниченное время на голос (голосовать за самого себя нельзя — сервер это проверяет), live-подсчёт по каждому кандидату, обработка ничьей, автозавершение по истечении времени (или досрочно хостом)
  - **Автоматическая победа по вместимости бункера**: у бункера есть реальная вместимость — число мест, всегда меньшее числа спустившихся игроков (генерируется вместе с остальными параметрами бункера и видно на экране катастрофы и во время игры). Как только число невыгнанных выживших сравнивается с вместимостью, игра автоматически завершается — показывается отдельный экран победы со списком выживших
  - **Общий чат с таймером обсуждения**: игроки переписываются в реальном времени (через поллинг), хост может запустить общий таймер обсуждения (например, на раунд или на ситуацию), который виден всем в чате и на игровом экране
  - Системные сообщения в чате обо всех ключевых событиях (создание комнаты, вход игрока, катастрофа, раунды, ситуации, голосования, исключения, сброс игры)
  - Случайные события каждого раунда (короткие карточки, всплывают автоматически у всех при переходе в новый раунд)
  - Тёмный постапокалиптический дизайн: текстура шума, виньетка, ржавые акценты, анимации карточек
  - **Звуковые эффекты и анимации** (по фидбеку игроков — «нужен хороший дизайн», «мало деталей и звуков, скучно», «друзья не поняли как играть»): процедурные звуки на Web Audio API (без внешних файлов), фоновые частицы-угольки на экране, рябь (ripple) на кликах по кнопкам, «влётывающие» с задержкой карточки игроков, вспышка новых сообщений в чате, конфетти на экране победы, подсказка «как играть» на игровом экране и автопоказ инструкции при первом визите

## Архитектура и данные

### Backend
- **Hono (TypeScript)** на Cloudflare Workers/Pages
- **Cloudflare D1** (SQLite) — единственное хранилище состояния игры; никаких данных в памяти или localStorage сервера
- Игрок на клиенте хранит только `{ code, token }` в localStorage — сам игровой прогресс целиком живёт в D1
- Приватность реализована на уровне SQL-запросов: при каждом запросе `state` сервер сравнивает токен запроса с токеном каждого игрока и либо отдаёт полную карточку (если это «я»), либо только раскрытые поля (`revealed_json`)
- Клиент **поллит** `GET /api/room/:code/state` каждые ~2.5 сек (без WebSocket/Durable Objects — облегчённый стек Cloudflare Pages)

### Таблицы D1 (`migrations/0001_initial_schema.sql`)
- `rooms` — код комнаты, статус (`lobby`/`catastrophe`/`game`/`ended`), катастрофа, бункер (включая поле `capacity` — вместимость), раунд, порог голосования, текущее событие/ситуация, активный таймер (`timer_json`). При достижении `capacity` статус автоматически становится `ended`; отдельная таблица победителей не нужна — победителями считаются все claimed-игроки без `excluded` в момент завершения
- `players` — места комнаты (пустые слоты создаются заранее), токен владельца, все характеристики, `revealed_json` (какие поля раскрыты), флаг исключения
- `chat_messages` — сообщения чата и системные события
- `votes` / `vote_ballots` — сессии голосования и индивидуальные бюллетени (один голос на игрока, можно менять до дедлайна)

### Frontend
- Vanilla JS SPA (`public/static/app.js`) без сборки фреймворка, Axios для запросов, Font Awesome, Google Fonts (Oswald + Rubik)
- **i18n**: словарь `I18N = { ru, en }` + функция `t(key, vars)` с интерполяцией `{placeholder}` и запасным вариантом (нет перевода → русский → сам ключ). Язык хранится в `localStorage` (`shelter_lang_v1`) и переключается кнопкой, вынесенной напрямую в `document.body` (вне `#app`), чтобы не пересоздаваться при каждом ре-рендере/поллинге
- Экраны: **Лендинг** → **Играть** (создать комнату / войти по коду) → **Выбор места** → **Лобби** → **Катастрофа** → **Игра** (карточки + сайдбар с голосованием и чатом); отдельно доступна страница **Настройки** (заглушка «в разработке»)
- Игровой экран рендерит только те данные, которые прислал сервер — чужие нераскрытые характеристики физически отсутствуют в ответе, а не просто скрыты в CSS

## API-эндпоинты (`/api/room/*`)
| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/create` | Тело: `{ playerCount }`. Создаёт комнату с пустыми местами, возвращает `{ code }` |
| `POST` | `/:code/join` | Тело: `{ slot, name }`. Занимает место, возвращает `{ token, isHost, ...state }` |
| `GET` | `/:code/state` | Заголовок `X-Player-Token`. Полное состояние комнаты с приватностью под запрашивающего |
| `POST` | `/:code/start` | Хост. Генерирует катастрофу, бункер и характеристики всем игрокам |
| `POST` | `/:code/reroll-catastrophe` / `/reroll-bunker` | Хост. Перегенерирует катастрофу/бункер |
| `POST` | `/:code/enter-bunker` | Хост. Переводит комнату в статус игры, раунд 1 |
| `POST` | `/:code/reveal` | Тело: `{ field }`. Игрок раскрывает/скрывает своё поле |
| `POST` | `/:code/reroll-attr` | Тело: `{ field }`. Игрок перебрасывает своё ещё нераскрытое поле |
| `POST` | `/:code/exclude` | Тело: `{ playerId }`. Хост исключает/возвращает игрока. После исключения автоматически проверяется условие победы (вместимость бункера) |
| `POST` | `/:code/next-round` | Тело: `{ seconds }`. Хост. Новый раунд + событие + таймер обсуждения |
| `POST` | `/:code/situation` | Хост. Озвучивает случайную ситуацию |
| `POST` | `/:code/timer/start` / `/timer/cancel` | Хост. Произвольный таймер обсуждения (для чата) |
| `POST` | `/:code/vote/start` | Тело: `{ seconds }` (15–3600, по умолчанию 90). Хост. Старт голосования (только с порогового раунда, и только если живых игроков ≥ 3 — иначе `not_enough_alive_for_vote`) |
| `POST` | `/:code/vote/cast` | Тело: `{ targetPlayerId }`. Голос (можно менять до дедлайна). Голосовать за самого себя нельзя (`cannot_vote_self`) |
| `POST` | `/:code/vote/cancel` | Хост. Досрочно отменяет активное голосование без исключения кого-либо (`status='cancelled'`, сбрасывает таймер, пишет системное сообщение) |
| `POST` | `/:code/vote/finalize` | Хост — в любой момент; любой игрок — после истечения времени. После исключения проигравшего автоматически проверяется условие победы |
| `POST` | `/:code/chat` | Тело: `{ text }`. Отправка сообщения в чат |
| `POST` | `/:code/reset` | Хост. Сброс комнаты в лобби с сохранением мест |

## Как пользоваться
1. **Главное меню**: на лендинге нажмите «▶ Играть» — откроется страница с двумя блоками: «Создать комнату» и «Войти по коду». Кнопка «❓ Как начать игру» открывает краткую подсказку прямо на главном экране; «⚙ Настройки» ведёт на страницу с полными правилами, именем по умолчанию и разделом «О проекте»; «Наш Telegram-канал» открывает канал проекта.
2. **Создание комнаты**: выберите количество мест и нажмите «Создать комнату» — получите 5-символьный код. **Приглашение**: передайте код (или скопируйте ссылку-приглашение кнопкой рядом с кодом) остальным игрокам — каждый открывает тот же сайт, нажимает «Играть» → «Войти по коду».
3. **Выбор места**: каждый видит сетку мест — свободные кликабельны. Нажав на свободное место, игрок вписывает своё имя и подтверждает — так он «становится» этим персонажем. Первый занявший место автоматически становится хостом.
4. **Лобби**: хост видит кнопку «Начать катастрофу» (активна от 2 занятых мест). Остальные видят статус ожидания.
5. **Катастрофа**: хост может перегенерировать катастрофу/бункер или сразу «Спуститься в бункер».
6. **Игра**: карточки расположены «ареной» — своя карточка по центру, остальные по бокам. Лицевая сторона каждой карточки — постер с силуэт-иконкой, именем и профессией; клик по карточке переворачивает её и показывает полные характеристики (у себя — все, у других — только раскрытое). Раскрытие/переброс доступны только на своей карточке.
7. **Раунды**: хост нажимает «Следующий раунд» — у всех всплывает модалка с событием, счётчик раунда растёт.
8. **Ситуации**: хост нажимает «Ситуация» — у всех появляется модалка с развёрнутым текстом для обсуждения вслух.
9. **Чат**: справа общий чат с сообщениями и системными событиями; хост может запустить таймер обсуждения — он виден всем как обратный отсчёт.
10. **Голосование**: с 3-го раунда (и только если живых игроков ≥ 3) хост может запустить голосование с таймером от 15 сек до 60 минут (по умолчанию 90 сек). Пока оно активно: прогресс-бар «сколько уже проголосовало», живой индикатор текущего лидера (или ничьей, или «пока нет голосов»), список тех, кто ещё не проголосовал, и персональная подсказка каждому игроку — проголосовал он или нет. На карточках других игроков виден живой счётчик полученных голосов (с подсветкой у лидера) и кнопка «Голосовать против». По истечении времени голосование автоматически завершается — исключается набравший больше голосов, при ничьей никто не исключается. Хост может завершить раньше или полностью отменить голосование (с подтверждением) без исключения кого-либо.
11. **Победа**: как только число выживших (не исключённых) сравнивается с вместимостью бункера — после ручного исключения хостом или после голосования — игра автоматически заканчивается: показывается экран победы со списком выживших и списком тех, кто остался на поверхности. Дальнейшие игровые действия (раунды, ситуации, голосования, исключения) блокируются сервером до сброса игры.
12. **Новая игра**: хост может сбросить партию в лобби (с подтверждением, либо прямо с экрана победы) — все остаются на своих местах для новой раздачи.

## Реализованные функции
- ✅ Игра переименована в **SHELTER** (везде в интерфейсе и заголовках), чтобы не совпадать с брендом коммерческой настольной игры
- ✅ Лендинг с главным меню (Играть / Как начать игру / Настройки / Наш Telegram-канал) и отдельной страницей «Играть» (создать комнату / войти по коду)
- ✅ Красивый анимированный экран загрузки (вращающиеся кольца, пульсирующая иконка, прогресс-бар)
- ✅ Страница «Настройки»: имя по умолчанию (сохраняется в localStorage и предзаполняется при занятии места), полные правила игры, блок «О проекте»
- ✅ Кнопка-подсказка «Правила игры» (❓) на игровом экране — открывает модалку с полными правилами в любой момент партии
- ✅ Настоящий мультиплеер: комнаты по коду, каждый игрок со своего устройства
- ✅ Выбор своего места/персонажа в лобби
- ✅ Серверная приватность характеристик (видно только владельцу, пока сам не раскроет)
- ✅ Хост-права на управление игрой (катастрофа, раунды, ситуации, голосование, сброс)
- ✅ Голосование с таймером, разблокируемое с 3-го раунда, автозавершение по истечении времени, обработка ничьей, запрет голосовать за самого себя
- ✅ **Доработанная система голосования**: минимум 3 живых игрока для старта (`not_enough_alive_for_vote`), live прогресс-бар «сколько уже проголосовало», индикатор текущего лидера/ничьей/«пока нет голосов», список ожидаемых голосов («кто ещё не проголосовал» / «все проголосовали!»), персональная подсказка игроку о статусе его голоса, отметки-галочки у проголосовавших в списке, подсветка лидера в списке голосования и на его карточке, живой счётчик голосов прямо на карточках игроков, возможность хоста досрочно **отменить** голосование с подтверждением (без исключения кого-либо)
- ✅ **Мобильная адаптация карточек игроков**: увеличенные зоны нажатия (кнопки раскрытия/переброса/голосования доведены до ~38–44px под палец), уменьшенные отступы для плотной компоновки на узких экранах, перестроенный сайдбар голосования (кнопки в столбик, поля на всю ширину) в медиа-запросе `max-width: 640px`
- ✅ **Новый дизайн карточек игроков «арена» + переворот по клику**: собственная карточка игрока расположена по центру, карточки остальных игроков — по бокам (чередуются слева/справа), на десктопе это flex-раскладка в ряд, на мобильных (`max-width: 640px`) — вертикальный стек с карточкой «я» первой. Лицевая сторона карточки — постер в тёмной стилистике (по мотивам референса): крупная полупрозрачная силуэт-иконка профессии, метки «Вы»/«Хост», бейдж числа голосов, имя и профессия капсом, ряд мини-индикаторов (точки/полоски) числа раскрытых характеристик, штамп «исключён» по диагонали для выбывших. Клик по лицевой стороне запускает 3D-переворот (`perspective` + `preserve-3d` + `rotateY(180deg)`) и показывает оборотную сторону с полным списком характеристик, кнопками раскрытия/переброса и голосования — как раньше. Состояние «какие карточки развёрнуты» хранится на клиенте и переживает фоновый поллинг (карточка не «схлопывается» сама во время обновления данных)
- ✅ **Обновлённый главный экран (лендинг)**: анимированная эмблема (иконка радиации в двух вращающихся кольцах разного направления), три информационных бейджа («4–16 игроков», «Свой телефон или ПК», «Старт за минуту»), акцентная кнопка «Играть» с бегущим бликом (`btn-shine`), декоративный атмосферный фон (свечение/сетка/точки, тот же компонент, что и на экранах катастрофы/победы), вторичные кнопки сгруппированы в аккуратный ряд. Экран не участвует в поллинге состояния комнаты, поэтому все анимации там бесконечные и безопасные (не «мигают»); учтён `prefers-reduced-motion`
- ✅ Автоматическое условие победы: вместимость бункера (всегда меньше числа игроков) генерируется вместе с параметрами бункера, отображается на экране катастрофы и во время игры; при достижении — отдельный экран победы, блокировка дальнейших игровых действий до сброса
- ✅ Общий чат с таймером обсуждения и системными сообщениями о событиях игры
- ✅ Генератор персонажей, катастроф, параметров бункера, ситуаций для озвучивания
- ✅ Поллинг состояния комнаты (обновление каждые ~2.5 сек) без визуального «мигания» экрана — анимация появления проигрывается только при реальном переходе между экранами, а не при каждом фоновом обновлении
- ✅ Атмосферные «сцены»: декоративный фон с эффектами (свечение, сетка, точки) на экранах катастрофы (красная тема) и победы (зелёная тема), плюс разовая анимация появления карточки/иконки; визуализация бункера — отсеки/капсулы игроков со статус-лампочкой (свободно / занято / моё место / исключён) в лобби и на игровом экране

Выбор языка сохраняется в `localStorage`

Реализовано без изменений на backend — БД и API продолжают работать с русским текстом как единственным источником данных:
  - Словарь `CONTENT_EN` (417 записей, точное соответствие "русский текст → английский текст", проверено на 100% покрытие всех строк `src/data.ts`) + функция `tc(text)`, которая ищет точную русскую строку в словаре и подставляет перевод, либо возвращает исходный текст без изменений, если перевода нет (тот же принцип «мягкого фолбэка», что и у `t()` для интерфейса)
  - Отдельная функция `translateSystemMessage(text)` — по регулярным выражениям распознаёт 15 шаблонов системных сообщений чата (создание комнаты, вход игрока, катастрофа, раунды, ситуации, голосования, исключения, победа, сброс игры и т.д., формируемых сервером в `src/rooms.ts`) и пересобирает их на английском, переводя вложенные названия катастроф/событий/ситуаций через `tc()`
  - `tc()` применяется во всех местах отображения контента: экран катастрофы (заголовок/описание), параметры бункера (везде, включая мини-панели на игровом экране), профессия (карточка игрока и экран победы), значения раскрытых характеристик, модалка раундового события, модалка ситуации (категория/заголовок/текст)

1. Добавить более быстрые обновления через Durable Objects/WebSocket, если поллинг раз в 2.5 сек окажется недостаточным.

5. Записать настоящие звуковые файлы (озвучка/музыкальный эмбиент) вместо процедурного синтеза, если понадобится более «богатое» звучание.
